# 產品名詞

- 狀態：已採用
- 更新：2026-10-19
- 英文版：[Product terminology](terminology.en.md)

## 名詞定義

| 中文 | 英文 | 定義 |
|---|---|---|
| 專案 | Project | 管理工作路徑、便箋與多個工作階段。 |
| 工作階段 | Session | Hestia 管理的一個 tmux 工作階段，包含多段對話；結束後仍可保留名稱與對話紀錄。 |
| 對話 | Conversation | 工作階段內一段獨立的 AI CLI 對話，有自己的訊息、紀錄與摘要。 |
| 收件匣 | Inbox | 還沒歸到任何專案的便箋放的地方。一直存在，不能改名或刪除；名稱由 App 依介面語言顯示，不存在資料裡。 |

層級：**專案 → 工作階段 → 對話**。一個工作階段可以保存多段對話，同時只執行一個 CLI。CLI 原生的 session ID 辨認的是對話，不是 Hestia 的工作階段。

## 介面用詞

| 中文操作 | 英文操作 | 範圍與結果 |
|---|---|---|
| 新增工作階段 | New session | 建立另一個 tmux；選擇 CLI 與帳號後開始對話。 |
| 在此專案新增工作階段 | New session in this project | 在既有專案的指定工作路徑建立工作階段。 |
| 新增專案與工作階段 | New project and session | 同時新增專案及其第一個工作階段。 |
| 建立新對話 | New conversation | 在目前工作階段中結束目前 CLI，再啟動新的對話；舊對話保留。 |
| 切換對話 | Switch conversation | 選擇要查看的對話；繼續執行需使用「繼續對話」。 |
| 繼續對話 | Continue conversation | 恢復已保存的對話；依能力重新啟動 CLI，必要時重建 tmux。 |
| 結束工作階段 | End session | 停止 CLI 與 tmux，工作階段仍留在清單中供查看。 |
| 重新命名工作階段 | Rename session | 修改工作階段顯示名稱；不修改 CLI 對話名稱。 |
| 刪除工作階段 | Delete session | 結束 tmux 並移除清單項目，範圍包括該工作階段的所有對話；支援垃圾桶時可還原。 |
| 還原工作階段 | Restore session | 從垃圾桶回到清單；不自動執行 CLI。 |
| 永久刪除工作階段 | Permanently delete session | 從垃圾桶移除，無法還原；主機保存的對話紀錄檔不受影響。 |
| 查看摘要 | View recap | 顯示該工作階段中各段對話的摘要。 |
| 分工 | Division of work | 交接、指派、支線的統稱：這件事要誰來做。從輸入框的「誰來做」發起，輸入框的文字直接當任務。 |
| 交接 | Handoff | 換別的 LLM 接手同一件事：原本的 CLI 停下，在同一個工作階段由另一個帳號或 CLI 繼續。 |
| 指派 | Delegate | 交出一件工作：在新的工作階段和 worktree 裡做，做完交回來，由你驗收。 |
| 支線 | Branch line | 帶著目前的記憶另開一條線：在新的工作階段和 worktree 裡同時進行，不用回報。 |
| 封存 | Archive | 結束支線或指派的工作階段、移除它的 worktree（branch 已合併才刪），只留下紀錄；清單上預設不顯示，可以展開查看，不能再恢復執行。取代舊的「收掉」與指派的「清理」。 |
| 相關工作 | Related work | 這個工作階段發起的指派、支線與交接紀錄；進行中的在輸入框上方一行列出，全部可從標題選單「相關工作…」打開分頁面板。 |
| 額度不夠時 | When usage runs low or out | 額度快用完或已用完時，這個工作階段的做法（不處理、等重置後自動繼續、交接給其他帳號）。 |
| 段 | Part | 一個工作階段裡的一段對話（第 N 段）。各段在聊天畫面接成一條，段落之間的分隔線說明記憶有沒有延續：交接來的段只讀了交接檔，其他新的段沒有延續前面的記憶。 |

## 用語原則（2026-10-13）

以台灣慣用、書面但不艱澀的說法為準；同一個意思只用一種說法。

| 用 | 不用 | 說明 |
|---|---|---|
| 封存 | 收掉、清理（指派） | 見上表。git 面板裡清理 worktree 的「清理」維持原樣。 |
| 恢復 | 接回 | 讓已結束的對話重新執行。 |
| 收合／展開 | 收起、收折 | 介面元件的開合。 |
| 開啟 | 打開 | |
| 無法… | 沒辦法… | |
| 已達額度上限 | 撞到額度上限 | 只說「上限」時用「達到上限」。 |
| 自行繼續 | 自己繼續 | CLI 自己在重置後繼續；App 排定的是「自動繼續」。 |
| 停止等待 | 不等了 | |
| 查看… | 看… | 查看更多、查看終端機、查看來源。 |
| 讀取／修改／執行 | 讀／改／跑 | 一輪過程的工具摘要；檔案數用「個檔案」。 |
| 產生 | 生成 | |
| 繪製 | 渲染 | 圖表。 |
| 連接埠 | 埠、連線埠 | |
| 模型 | model | 啟動方式、帳號等設定項目一律中文；CLI 原生名稱、模型名稱維持原文。 |
| 啟動方式 | profile | |
| subagent | 子代理、子 agent | 保留原文，和 CLI 畫面一致。 |
| ·（前後空格） | ・ | 行內分隔符號。 |
| 主機設定、沿用主機設定 | 全域、跟隨全域 | 存在主機上、所有連到這台主機的裝置共用的設定（2026-10-19）。 |
| 便箋 | 便簽 | |
| 自動整理 | 自動模式 | 便箋的自動整理。 |

介面文字放在 `web/src/i18n/locales/` 的語系檔，程式只寫 key（例如 `t('settings.locale.hint')`）。改既有文案時改 `zh-TW/` 裡那個 key 的值，英文在 `en-US/` 的同名檔，同時修改；程式不用動。後端給人看的文字（推播、狀態、`hestia` 指令的輸出）在 `api/src/i18n/locales/` 的同名檔，同樣中英文一起改；寫給 LLM 的交接檔、提示與紀錄在 `api/src/i18n/prompts/`，只有中文，不套用這份用詞（改了就是改變 LLM 收到的內容）。

## 語言與適用範圍

- 介面預設為繁體中文；中文模式顯示「專案／工作階段／對話」，切換英文才顯示 Project／Session／Conversation。
- 所有入口、快捷鍵說明、命令面板、表單、無障礙標籤、通知、錯誤、狀態、垃圾桶與使用分析遵循此定義。
- 工作階段的快捷鍵作用於當下開啟的工作階段，不由滑鼠位置、清單搜尋、收折狀態或其他列的焦點決定。
- 工作階段清單的搜尋是找工作階段；「搜尋對話」是找對話文字。摘要的「對話」與使用分析的「CLI 對話」指 Conversation。
- 一般產品文案用「工作階段」。品牌、原生 tmux 指令、程式/API 識別字、原始錯誤、CLI 輸出、路徑、使用者名稱與內容維持原文。技術診斷確實在描述 tmux 本身時可保留 tmux。
- 程式裡既有的 `ManagedSession`、`Conversation`、`tmuxName`、URL、欄位與儲存鍵不因翻譯而改名。
- 歷史需求、決策與實測紀錄保留當時原文；目前產品文件與新的介面文案以本文件為準。
