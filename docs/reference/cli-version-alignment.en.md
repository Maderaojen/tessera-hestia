# CLI version alignment

- Updated: 2026-10-22
- 中文: [cli-version-alignment.md](cli-version-alignment.md)

This table records, for every feature in the code that depends on a CLI's screens, file formats or behavior, which CLI version it was verified against and when. CLIs update themselves or get updated by hand, and afterwards these features can break silently (for example, Agy 1.2.10 → 1.2.12 added a status bar, and the trust card stopped appearing). This table lets us compare "the version installed now" with "the version the code is aligned to" and see what needs re-verifying.

**This is the only such table.** Code comments and other documents still say "what was observed in which version", but "which version it is aligned to now" is decided here.

## Installed versions

| CLI | Installed version | Checked | How |
|---|---|---|---|
| Claude Code | 2.1.301 | 2026-10-16 | `claude --version` |
| Codex CLI | 0.163.0 | 2026-10-16 | `codex --version` |
| Agy (Gemini) | 1.3.3 | 2026-10-16 | `agy --version` (updates itself) |
| Gemini CLI (legacy) | Not installed | 2026-09-27 | `gemini --version` |

Janus accounts run the same CLI executable with a different settings folder, so they have no separate version.

## Feature alignment

"Aligned version" is the last version actually verified. Anything older than the installed version is marked **re-verify**: it doesn't mean it is broken, only that nobody has checked.

## When a CLI is updated

1. Find the installed versions with the commands above and update the "Installed versions" table.
2. Compare with the feature table and list the items whose aligned version is older than the installed one.
3. Re-verify them in order of risk: trust screens, identity binding and content parsing first, since when they go wrong users see it, or conversations get mixed up:
   - **Screens** (trust screens, idle / busy readings): start the CLI in an isolated tmux (`tmux -L <name>`) and capture the screen with `tmux capture-pane -p`. Trust screen captures go into `api/test/fixtures/startup-prompts/` (naming rules in the README there); then run `npx vitest run test/runtimes-startup-prompt.test.ts`.
   - **Identity and file formats**: redo them in an isolated environment, the way the 2026-09-24 isolated test did (record not published).
4. If behavior didn't change, only update this table's aligned versions and dates. If it did, fix that CLI's own spec or driver, note the difference observed, then update this table.
5. Add a line to the change log below.
